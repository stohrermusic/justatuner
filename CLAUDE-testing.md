# JustATuner — testing

*The test suites, the frozen-build probe, the screenshot tour, and the smoke-test patterns. Companion to CLAUDE.md; same rules, same voice. Edited in the same commit as the code it describes.*

## Tests

```bash
python tools/run_tests.py              # every tools/test_*.py, PASS/FAIL per suite
python tools/run_tests.py engine       # suites whose name contains a word
python tools/run_tests.py --skip gpu --allow-missing sounddevice
python tools/run_tests.py --visible    # Windows: windows on this desktop (default: a private one, nothing shows)
python tools/hidden_desktop.py python tools/test_layout.py   # one suite, or any command, off screen
python tools/test_tuner_engine.py      # one suite directly
python main.py --selftest              # SELFTEST OK / SELFTEST FAIL, exit 0/1
python main.py --tour all --shots DIR [--appearance dark]   # screenshot every stop
```

Each `tools/test_*.py` is a standalone script, not pytest; the runner executes each in its own interpreter from the repo root (same as SSC). Fourteen suites, 563 checks, about 120–130 s locally as of 2026-11-28 (twelve suites, about 440 checks and 95 s on 2026-10-07). `tools/measure_bleed.py` is a measuring tool, not a test: it plays the drone through the real speakers and reports what the real mic hears. Every engine built in a test stubs its stream openers or uses `synthetic_hz`; see the traps.

A suite that cannot run (no display, no audio library or sound server) prints a line starting "Skipping" and exits 0; the runner shows it as `skip` and ends with how many "skipped themselves and tested nothing". Read that line on a CI run: a green Linux job with the GUI suites skipped has tested only the math. A passing suite can also leave one check out and say so on a line starting "SKIP"; the runner repeats those lines after its totals ("check(s) were left out inside suites that passed"). The same goes for a number a suite measures but does not judge: print it on a line starting "INFO" and the runner repeats it, whole, under "line(s) marked INFO in suites that passed" (2026-11-26). That is where the Mac runner's frame rates are read: in the test job's log, after the totals. A number printed any other way by a passing suite is seen by nobody.

**On Windows the suites run on a private desktop** (2026-11-25, `tools/hidden_desktop.py`, from SSC). `tools/run_tests.py` re-runs itself on a desktop of its own and every suite, child interpreter and tour it starts inherits it: nothing shows on, or takes the focus from, the desktop someone is using. The runner's first line says where the suites are. `--visible` (or `JUSTATUNER_VISIBLE=1`) keeps them on your desktop; macOS, Linux and CI (`GITHUB_ACTIONS`) are untouched. A single suite, a probe or a tour goes there with `python tools/hidden_desktop.py <command...>`; running `python tools/test_x.py` directly still opens its windows in front of you. Measured there on this PC: all fourteen suites pass, the GPU renders, the screen size is the same, the paced-loop checks hold 60. Two limits. The screen cannot be grabbed from it, so `test_tuner_canvas`'s GPU stripe-direction check from screen pixels leaves itself out (the runner says so): run `python tools/run_tests.py tuner_canvas --visible` after touching either renderer's direction, and a tour with `--shots` uses the same grab, so it needs the real desktop too (not tried there). And a native dialog nobody stubbed would hang there unseen until the runner's 600 s timeout (measured in SSC, not planted here), so the messagebox rule below matters more, not less. It keeps tests off the screen, not off the processor.

- `test_tuner_engine` — pure math, no display: the Hann estimator on a pure lobe (<0.01 bin) and on a decaying note over every offset in a bin (measured bounds: 0.002 bin at 300 ms, 0.01 at 100 ms, 0.12 at 20 ms), in-tune A1–A6 sweeps (pure sine <0.5 c; with a −6 dB H2 <1.0 c, C2–A6 <0.5 c), off-pitch A2–A5 within 0.15 c, the strobe standing still on an in-tune note, B5 26 c flat, a sharp note raising the phase and a flat one lowering it, a ring following only its own partial (an A4 in a rumbling room: the rings with no partial turn with the wheel in every frame and none goes left; octave partials 4 c and 9 c sharp still read back on their own rings), numpy surviving a blocked sounddevice (child interpreter), and the synthetic source through `analyze()`.
- `test_audio_utils` — the ring buffer, `synthetic_tone` phase continuity, the estimator's climb and clamp, the sample-rate fallback for input and output on a fake sounddevice, `TunerEngine` on a 16 kHz device, the saved-device fallback, the stale-stream restart, `silent_seconds`, both engines and `audio_latency` importing with no audio when sounddevice raises `PortAudioError` at import (child interpreter), `pitch_or_default`.
- `test_exerciser_engine` — YIN over C2–C7 at 44.1 kHz and D2–C6 at 16 kHz, the JI interval math, note naming, transposition, presets and voicings, `get_pitch` on the synthetic source, headphones mode untouched, the sample-drone notch documented, and the output device on a stand-in sound library: the chosen device is the one opened, a refused one falls back to the default with the reason kept, no output at all is reopened when the device is back, an output whose callback has stopped is closed and opened again inside the pacing (the room dropped, the drone listened to again), a pick while running reopens, no health check with the synthetic source.
- `test_drone_cancel` — the speakers-mode cancellation on a simulated room (delay, echo, noise, clock drift): the drone alone reads no pitch (53 dB of the fundamental removed), just intervals over the bleed within 0.02 c, a locked unison held 30 s is not learned away, 50 ppm drift still cancelled after 60 s, headphones mode exact, a note change re-listens, the room table (back to a known chord with 20 ppm drift and no new listen: 59.8 dB removed, ppm learned within 0.1), the click-free chord change, the sample drone keeps the notch.
- `test_progression` — notation round trips and rejections, timing in all three modes, presets, save/load, and the player on a fake clock and a fake engine: count-in, step changes at 2/4/6/8 s at 120 bpm, looping, next(), the calibration sequence and its skip, manual mode.
- `test_sample_pipeline` — the WAV reader (16/24/32-bit PCM, float32/float64, stereo), sample install (trim, pitch, period-aligned crossfade, seam, level), pitched playback, synth output, recording, save and clear.
- `test_config` — settings load/merge/corruption/round trip, device resolution by name, prefix and legacy index, the device filter, the playback-device list (only the default output's host API, no aliases or duplicates) and the saved output by name (found at a new index, kept when not connected, both keys in the defaults), the rescan on a fake sounddevice, logging.
- `test_audio_latency` — the loopback measurement on a mocked device: delays, noise, echo cancellation, disagreeing chirps, rate fallback.
- `test_gpu_tuner` — the `tuner_render` API, the renderer.rs / view.py source contract, a 3500×1500 surface, `adapter_info` / `present_mode`, 60 frames timed, and the 30-failure fallback on the real app. Skips the wheel-dependent parts when the wheel is not built (set `JUSTATUNER_REQUIRE_GPU=1` on a machine that built it to make a broken wheel fail loudly) and the construction cases on a runner with no GPU surface.
- `test_tuner_canvas` — the real tuner tab end to end: pass 0 no mic (error text drawn and surviving a rebuild, MIC lamp dark), pass 1 canvas mode on the synthetic tone (12 wheels, A brightest, readout A / IN TUNE, lamp green, 0 c through the live path), pass 2 the GPU build (live renderer with zero failures, or the designed fallback with the CPU-mode notice). Both passes read which way the stripes travel from the picture: the engine is replaced by a stand-in that lights all twelve wheels at a given phase, the tab's own animate loop draws it, and the phase is raised 3°. Pass 1 reads the canvas items' coordinates (runs everywhere, including the Mac runner); pass 2 grabs the screen and reads ring 3 of every wheel (only where a real GPU renders; a covered window is a printed SKIP, or a failure under `JUSTATUNER_REQUIRE_GPU=1`). Frame pacing: `FramePacer` on a fake clock, a bare Tk loop with 4 ms of work paced to 60 a second under `fine_timer` (its rate and how late its timers fired are printed on every run; judged at 57–63 fps on Windows and Linux, printed only on macOS, where a shared runner has read 47 to 64, with its timers 9 ms late at the median on the one run that recorded it), and the GPU tab's own loop on the 60 setting (median frame within 55–65 fps where a frame keeps Tk busy under 85 % of the period, printed otherwise; every frame's idle work must have run before the next frame starts). The canvas tab's rate is measured and printed as `INFO`, never judged: it is bound by its redraw. Then two start-up cases: `"reference_pitch": "abc"` in the settings file, and a child interpreter whose sounddevice raises at import (the app builds, both tabs say why).
- `test_drone_tab` — the real drone tab end to end on a just major third above its root: Major 3rd, 5:4, LOCKED, "Playing: E3", the ET-difference line, Bb transposition, every visualizer mode drawing without a Tk exception and still inside the scope after the window is shrunk to its minimum and grown back, the "Phase Wheel" mode migration, a progression in seconds mode whose interval readings follow the moving root (Major 3rd → Major 7th → Major 6th → Major 3rd), manual mode on the space key (and not from a text field), the Next button, drone-off stops it, Refresh Devices (one rescan with the streams closed, the late microphone listed, the saved one found by name at its new index), the output device (the line under the DRONE status says "Output: system default", the Output Device menu lists the playback devices, a pick reopens the output on it and is saved by name, Refresh Devices finds it at a new index, a missing one falls back and is named in the line, no output at all is said with its reason; the engine's output opener is a stand-in from that point), tab switch, save.
- `test_hidden_desktop` — the private desktop: when the run moves (Windows only; not in CI, not with `--visible` or `JUSTATUNER_VISIBLE=1`, not twice), checked on every platform so the suite never skips itself; then, on Windows, a child started through `rerun_hidden` opens a real Tk window, which must be listed among its own desktop's windows and absent from this process's desktop and from "Default"; exit code and output come back, also through a pipe; a suite started by `run_tests.py` is on a private desktop and the runner's first line names it; `--visible` keeps it here; then, on every platform again, a planted "SKIP" line and a planted 250-character "INFO" line in a passing suite are repeated in the runner's summary, the INFO line whole. Its own window is 200×80 and opens only on the private desktop.
- `test_layout` — nothing on either tab is cut off at real window sizes: the window's own minimum, 1280×621 (maximised on a 1920×1080 laptop at 150 %) and 1366×669 (a 1366×768 one). Walks every widget of both tabs for one that sticks out of its parent or is given less than it asks for; only the wheel area may give. Also: the minimum is what the tabs ask for and fits both laptops, the motor pilot stays centred in the tuner bar, the scope is square, between its limits, full size on a tall window, with its bezel redrawn. Starts no engine (the tab-change handler is unbound); sizes that do not fit the screen are printed, not judged.
- `test_tour` — `run_tour` with screenshots off as a gate on every platform (14 stops, no error), Tuner Settings opening with "System Default" after one rescan with the tuner stopped round it (a late microphone listed, picking it saves it by name and restarts the tuner on it), the latency dialog, the progression editor (preset pick, bad-chord status line, the picker, Save, Use, Delete).

Rules the suites follow, each from a trap above: an isolated profile via **`JUSTATUNER_CONFIG_DIR`** set before `config` is imported (never the user's settings); `builtins._` installed before importing `tuner.view`; `tkinter.messagebox` stubbed so the exception hook's dialog cannot block; **`JustATunerApp(autostart=False)`** so the test sets `synthetic_hz` before the first start and starts via `app._on_tab_changed()`; frames driven with `root.after(ms, root.quit); root.mainloop()`, never a `root.update()` loop; `check()` fails on a returned `False` as well as on an exception; `config.rescan_input_devices` stubbed wherever a device list is opened (no suite re-initialises the real PortAudio); an engine given `running = True` by hand has both `_start_input_stream` and `_start_output_stream` stubbed (`get_pitch()` reopens either); `focus_force()` before a generated key event.

**`--selftest`** (`_selftest()` in main.py) builds both tabs in a withdrawn root, runs the tuner on the synthetic tone (≥20 frames, readout A, no error state), switches to the drone tab on a synthetic just major third and requires the panel to say "Major 3rd", and exits 0/1 without saving. CI runs it against the frozen binary on every platform — the one check that runs the shipped bundle. **`--tour all --shots DIR`** (`run_tour()`) walks 14 stops — tuner with the real mic, tuner on the tone, Tuner Settings, the drone tab and each of its six visualizer modes, a progression running, the progression editor, the latency dialog, the user guide — screenshots each cropped to the app's windows, and writes `tour-done.txt` with each shot's mean brightness and any step errors. Help > About is a native messagebox and is not toured. Modal stops work because each stop's finish is scheduled with `after()` before its open is called. The macOS build job runs the tour light and dark and uploads `mac-tour`; those pictures are how the Mac UI gets reviewed. Driven on this PC (2026-10-06, the 12 stops it then had, three findings fixed). On a Mac it has run only on the CI runner, light and dark, on every push since 2026-10-06; no person has driven the app on a Mac.

## Smoke Testing Patterns

Patterns that caught real bugs during the v1.1.3 work; use them before claiming a UI or audio change works:

- **Drive the real app on a hidden root.** `app = main.JustATunerApp(autostart=False); app.root.withdraw()`, then drive frames with `app.root.after(ms, app.root.quit); app.root.mainloop()` (not a `root.update()` loop — see the traps). Select tabs with `app.notebook.select(app.exerciser_frame)` (the queued tab event starts that tab), poke engine state, read widgets. Withdrawing avoids flashing a window at whoever is watching the screen (and them closing it mid-test); for a probe that needs a shown window, run it through `python tools/hidden_desktop.py` instead. Widget sizes are still available via `winfo_reqheight()`; wheels are not built while the frame is unviewable, but the readout labels still update.
- **Monkeypatch `tkinter.messagebox`** (`showerror`/`showinfo`/`showwarning` to print) before importing `main`, or the exception hook's error dialog blocks the update loop forever.
- **Open the lazy-import dialogs.** `tuner/view.py`'s settings dialog imports `config.get_input_devices` and `ui_dialogs.add_tooltip` *inside* `_tuner_open_settings`, so `import tuner.view` succeeding proves nothing; two releases shipped with the dialog raising ImportError. Call `app.tuner._tuner_open_settings()` and confirm a `Tuner Settings` Toplevel appears.
- **Mock sounddevice for the macOS-only paths.** Windows MME accepts any sample rate (it resamples), so the CoreAudio "Invalid sample rate" fallback never fires here. Set `tuner.engine.sd = FakeSD` where `FakeSD.InputStream` raises on 44100 and `query_devices` reports a 16 kHz default, then feed `engine._ring_buffer.write(sine)` and check `analyze()` lights the right wheel.
- **Silence detection can't be tested with the real mic** (it keeps resetting the timer); stub `engine.silent_seconds = lambda: 10.0` for the UI path and call `_audio_callback` with zeros/non-zeros directly for the engine path.
- **`python audio_latency.py`** runs the loopback latency test standalone. On the dev laptop the Intel Smart Sound mic array cancels its own speaker output, so use the Realtek "Stereo Mix" input to validate the pipeline, or mock `sd.playrec` to return a delayed copy of the signal.
- **Lint**: `ruff check --select F,E9 <files>`. `tuner/view.py` has ~43 baseline `F821 Undefined name _` hits because `main.py` injects `_` as a builtin; compare counts against `git show HEAD:<file>` rather than reading the raw total.
