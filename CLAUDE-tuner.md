# JustATuner — strobe tuner

*The tuner engine: FFT analysis, the Hann peak estimator, phase tracking, stream health, the synthetic source. The GPU renderer's traps are in CLAUDE.md's ledger and Per-Platform Constraints. Companion to CLAUDE.md; same rules, same voice. Edited in the same commit as the code it describes.*

## Tuner engine (`tuner/engine.py`)

12 chromatic pitch classes, each with seven concentric rings (one per octave). FFT-based pitch detection with per-pitch-class phase tracking — phase deviation drives the stroboscopic rotation effect. Magnitude normalization is gated: `max_mag` must exceed `threshold * 1.5` before normalizing to 0–1, otherwise all magnitudes are zeroed. This prevents sensitive mics from showing wheel activity on room noise.

Peak frequency (both the per-ring estimate and the strongest-octave estimate that drives the VU and the wheel phase) comes from `audio_utils.hann_peak_freq`, the Hann closed form — not a parabola, which read in-tune low notes up to 15 c off (see the traps). It is the one-neighbour form, the same function as SSC's `audio_utils.hann_peak_freq` on purpose (the two-neighbour form was tried from 2026-10-06 to 2026-11-25 and was no better; see the traps before changing it). Magnitudes are read as before.

**Which way the stripes travel** (2026-11-25). The engine raises a wheel's phase (and each ring's) for a sharp note and lowers it for a flat one. Both renderers turn a disc clockwise on screen for a rising phase: the shader draws `angle - phase` with its angle clockwise from the top, and `StrobeWheel.update` draws `base - phase` because canvas angles count counter-clockwise. The top row's window is at the top of its disc, where clockwise is rightward; the bottom row's (the seven naturals, `BOTTOM_ROW_PITCH_CLASSES`) is at the bottom, where clockwise is leftward, so `tuner.view.window_phases` negates the bottom row's phases before either renderer. Result, and the rule the gates state from the picture: a sharp note's stripes travel right in all twelve windows, a flat note's left. Change one renderer's sign and the other must follow; see the traps.

**A ring follows only its own partial** (2026-11-25). Every ring of a lit wheel is drawn, and by default it turns with the wheel (the wheel's phase follows its strongest octave), so the disc is solid. A ring leaves the wheel's phase and turns by its own measured pitch only while it has a real peak of its own: within `RING_OWN_MAX_CENTS` (50) of the ring's note, `RING_OWN_PEAK_RATIO` (4.0, 12 dB) over the larger of the bins `RING_OWN_PEAK_SPAN` (3) away, and for `RING_OWN_HOLD_S` (0.1 s) unbroken (`_ring_own_time`). That is what lets a piano's sharp upper partials drift on their own rings without letting room noise steer the rings where the note has nothing. Brightness is untouched: a ring is still lit by whatever clears the threshold. The numbers behind the three constants are in the traps.

**Frame pacing** (2026-11-25, `tuner/view.py`). The FPS setting is frames per second (`FRAME_RATES`). `_tuner_animate` ends by queuing `_tuner_arm_next_frame` with `after_idle`, so it runs after Tk has drawn the frame; it asks `FramePacer.next_delay_ms(period)` for the wait to the next frame's start on a clock timeline (never under 1 ms, no catch-up bursts) and arms `after()` with that. On Windows `fine_timer(True)` holds a 1 ms system tick from `_tuner_start` until `_tuner_stop` or a stream error (`_tuner_hold_fine_timer`); without it no rate between 32 and 64 fps is reachable. Measured here: 60 → 59.7–60.0 fps, 120 → 120, GPU renderer. The canvas renderer is limited by its own redraw (5–9 fps maximised on this 3840×2400 screen, about 30 at 1000×720), not by the pacing; that is open.

**The control bar** (`_tuner_ctrl_frame`) is a three-column grid: the slider groups, the motor pilot, the VU meter with the MIC lamp. Columns 0 and 2 are `uniform="side"` with weight 1, column 1 has weight 0 and takes only what the pilot asks for; equal sides are what keep the pilot centred. It fits from about 890 px (three equal thirds needed 1070; see the traps). A new control in a side group widens both sides: check `test_layout`.

`synthetic_hz` (default None) is the test/CI source: when set, `start()` opens no stream, sizes the ring buffer itself, and `analyze()` feeds `audio_utils.synthetic_tone` (fundamental + −6 dB H2, phase-continuous from `_synth_pos`) before the stale check. `silent_seconds()` stays 0 (no stream), so the MIC lamp reads green. Nothing in normal use sets it. It needs numpy only: `start()` succeeds with it on a machine with no sounddevice or no sound server (the view still shows its no-audio panel there, since `AUDIO_AVAILABLE` is false).

Audio stream health monitoring via `AudioRingBuffer.is_stale()` — if no new audio data arrives for ~1 second, the engine restarts the sounddevice stream. Recovers from silent callback death on Windows. The ring buffer is sized at open to `max(rate × 0.2 s, FFT_SIZE)` so a 16 kHz stream still fills one FFT frame.

`start(device)` falls back to the system default when the requested device won't open (unplugged since it was saved, grabbed exclusively, index shifted) and logs a warning; `_last_device` is updated so auto-restarts stay on the working device.
